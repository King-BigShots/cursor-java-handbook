# 计划模式与小项目实战

用 Codex 做稍完整的任务时，建议先 **计划、再执行**，避免 AI 直接改一堆不符合预期的文件。

## 计划模式是什么

开启 **计划模式** 后，Codex 会先：

1. 理解需求
2. 可能追问细节（在面板里选项回答）
3. 输出实现计划（步骤、文件列表、测试方式）
4. 你确认后再写代码或改文件

适合：静态网页、脚本工具、文档站点等小到中型任务。

## 实战：个人介绍页（静态 HTML）

### 准备

1. 新建空文件夹，例如 `D:\learn\my-page`
2. 在 Codex 中打开该文件夹作为工作区
3. 开启计划模式
4. 模型与速度选默认或「标准 + 较高智能」（以应用内为准）

### 示例提示词

```text
帮我做一个单页 HTML 个人介绍页：
- 标题：我的名字
- 一节「关于我」、一节「联系方式」
- 简洁样式，手机也能看
- 不要依赖后端，打开 index.html 即可浏览

请先给出计划，我确认后再写文件。
```

### 确认后检查

- 是否生成 `index.html`（及可能的 css）
- 本地双击 HTML 或用浏览器打开预览
- 不满意时用 **批注**（若内置浏览器支持）或继续对话：

```text
把主标题字号加大，联系方式改成列表。
```

## 内置浏览器预览

部分版本支持在侧栏打开预览。也可自己运行本地静态服务，例如：

```bash
# 在项目目录（需已安装 Python）
python -m http.server 8080
```

浏览器访问 `http://localhost:8080`。

## 额度意识

完整页面类任务消耗明显高于简单问答。做完可在 `/status` 或设置里查看剩余配额。

## 与 Java 学习的关系

本仓库主学 Java；用 Codex 生成网页是为了练 **提需求 → 审计划 → 验收结果**。写 Java 项目时同样适用：先让小任务跑通，再扩大范围。
